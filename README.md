# Project overview
[![CI](https://github.com/haxily/simple-rest-py/actions/workflows/ci.yml/badge.svg)](https://github.com/haxily/simple-rest-py/actions/workflows/ci.yml)

Main focus of this project is to understand API design in Python(Django).

## Cloning
You can clone the repo with:
```bash
git clone https://github.com/haxily/simple-rest-py.git
```

## Requirements
Requirements for the project can be found in requirements.txt file.  
First create your python environment:

## On linux/mac
```bash
python3 -m venv .venv
source .venv/bin/activate
```
## On windows
```bash
py -m venv .venv
.venv\scripts\activate
```
Then install using:
```bash
pip install -r requirements.txt
```

## Run with Docker (PostgreSQL)
The quickest way to run the full stack (Django + gunicorn + PostgreSQL 17):
```bash
cp .env.example .env          # then edit the secret key and password
docker compose up --build
docker compose exec web python manage.py createsuperuser
```
Open http://localhost:8000/api/docs/. Migrations run automatically on start-up; data lives in the
`pgdata` volume (`docker compose down -v` wipes it).

Settings are read from environment variables (see `.env.example`). When `POSTGRES_DB` is not set,
the project falls back to SQLite, so the local steps below still work without Docker.

## Endpoints
The users API is a DRF `ModelViewSet` registered on a router, so the HTTP method decides the action.

| Method | URL | Action |
|---|---|---|
| GET | `/api/users/` | List users |
| POST | `/api/users/` | Create a user |
| GET | `/api/users/{id}/` | Retrieve a user |
| PUT | `/api/users/{id}/` | Replace a user |
| PATCH | `/api/users/{id}/` | Partially update a user |
| DELETE | `/api/users/{id}/` | Delete a user |

Example body for POST / PUT:
```json
{
"name": "Peter",
"age": 25
}
```
`GET /api/` shows the browsable API root.

## API docs
Interactive OpenAPI docs are generated by drf-spectacular:

| URL | What |
|---|---|
| `/api/docs/` | Swagger UI (use **Authorize** to paste a JWT access token) |
| `/api/redoc/` | ReDoc |
| `/api/schema/` | Raw OpenAPI 3 schema (YAML) |

## Authentication
Reading (`GET`) is public. Creating, updating and deleting users requires a JWT access token.

> Note: the accounts that log in are Django's built-in `auth.User`. The `/api/users/` resource is
> the app's own `api.User` model (the data being managed) - they are separate tables.

Create an account, get a token, then send it as a `Bearer` header:
```bash
python manage.py createsuperuser

curl -X POST http://localhost:8000/api/auth/token/ -H "Content-Type: application/json"      -d '{"username": "admin", "password": "<password>"}'
# -> {"refresh": "...", "access": "..."}

curl -X POST http://localhost:8000/api/users/ -H "Authorization: Bearer <access>"      -H "Content-Type: application/json" -d '{"name": "Peter", "age": 25}'
```

| Endpoint | Purpose |
|---|---|
| `POST /api/auth/token/` | Get an access (30 min) + refresh (1 day) token pair |
| `POST /api/auth/token/refresh/` | Exchange `{"refresh": "..."}` for a new access token |
| `POST /api/auth/token/verify/` | Check whether `{"token": "..."}` is valid |

In the browsable API, use the **Log in** link (top right) instead.

## Validation
- `name`: required, max 100 characters, surrounding whitespace trimmed, must contain at least one letter.
- `age`: required integer between 0 and 150.

Invalid requests return `400` with per-field error messages.

## Filtering & pagination
List responses are paginated (10 per page by default, max 100):
```json
{"count": 14, "next": "http://localhost:8000/api/users/?page=2", "previous": null, "results": [...]}
```

| Query param | Example | Meaning |
|---|---|---|
| `name` | `?name=pet` | Name contains (case-insensitive) |
| `min_age` / `max_age` | `?min_age=18&max_age=30` | Age range (inclusive) |
| `search` | `?search=pet` | Search by name |
| `ordering` | `?ordering=-age` | Sort by `id`, `name` or `age` (`-` for descending) |
| `page` / `page_size` | `?page=2&page_size=5` | Pagination |

## Running tests
Tests use pytest-django. From the repo root:
```bash
pip install -r requirements-dev.txt
pytest                                   # run the suite
pytest --cov=api --cov-report=term-missing   # with coverage
```
GitHub Actions (`.github/workflows/ci.yml`) runs Django checks, a missing-migrations check,
OpenAPI schema validation and the test suite on every push to `main` and every pull request.
